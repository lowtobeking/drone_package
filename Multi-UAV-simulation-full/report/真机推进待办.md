## 📌 几条别忘的坑（都实际踩过）

1. **Jetson 不是 git 仓库** —— `/commit-push` 和 `git push sim` 都不会同步到机上，必须手动
2. **`ros2 topic list --no-daemon` 有发现竞态**（实测连查三次得 22/22/**0**），
   判链路一律用 `ros2 topic hz`
3. **PX4 的 INT32 参数经 MAVLink 按字节透传进 float 字段** —— 直接读会得到
   `1.4013e-45` 这类垃圾值，须按 `param_type` 重解释
4. **PX4 条件参数** —— `UXRCE_DDS_*` 要等 `UXRCE_DDS_CFG` 启用后才在 QGC 里出现
5. **`kill_at_s` 必须晚于编队就绪** —— 杀早了就绪门控永远超时，整个 trial 被丢弃
6. **`run_one_trial.sh` 用 `pkill -9` 收尾** —— SIGKILL 不执行 Python 的 `finally`，
   退出汇总打不出来，统计要用周期打印

## E. 2026-07-28 台架双向通讯排查记录

### 排查过程与结论

1. **初次检查**：`eno1` 为 `NO-CARRIER, state DOWN`，ping 飞控 `192.168.77.2` 100% 丢包，
   `microxrce-agent` 日志显示开机以来无客户端连接——**物理层未通**（飞控当时未上电）。
2. **飞控上电后复测**：`eno1` 恢复 `LOWER_UP, state UP`，ping 0% 丢包；`microxrce-agent`
   日志出现 `create_topic`/`create_datawriter` 等会话建立记录；`tcpdump` 抓到
   飞控（`192.168.77.2:5669`）持续发包到 Jetson `:8888`。
3. **飞控 → 机载电脑方向**（`ros2 topic hz` 实测，v1.16 固件）：

   | 话题 | 实测频率 |
   |---|---|
   | `/fmu/out/vehicle_status_v1` | ~1.98 Hz |
   | `/fmu/out/vehicle_local_position` | ~100 Hz |
   | `/fmu/out/battery_status` | ~10 Hz |

   飞行期间 `arming_state=1`（STANDBY/未解锁）、`armed_time=0`，全程安全。
4. **机载电脑 → 飞控方向：未验证成功**。尝试用 `mocap_launch.py sitl:=true` 起假动捕源
   测试，但 `sitl_mocap_source_node` 依赖 PX4 SITL 侧的 `vehicle_*_groundtruth` 话题
   （见 `docs/SITL动捕注入.md` §2），Jetson 上**没有 PX4-Autopilot 源码树**，该节点
   拿不到真值、pub=0Hz，bridge 侧也是"一帧位姿都没收到"——**没有任何数据（真的假的）
   打到飞控**，未构成风险，但也没验证到东西。已确认清理进程（注意：`pkill -f` 那次
   没杀干净，PID 变了，改用精确 PID `kill` 才成功，验证要用独立 ssh 调用查 `ps aux`）。
5. **额外发现**：Jetson 系统时钟未同步，`date` 显示 1970 年附近（服务"运行了56年"），
   不影响 XRCE-DDS 本身，但会干扰日志时间戳定位问题，值得找时间修（NTP/RTC）。
