## 1. 上电 + 链路自检
**⚠️ 上电顺序:先 Jetson(等 Agent active),后飞控** —— PX4 `uxrce_dds_client` 在 Agent
消失后不自动重连,反了要重启飞控。

```bash
# Jetson 上
systemctl is-active microxrce-agent          # 判据: active
ip -br addr show eno1                          # 判据: UP + 正确 IP
ping -c2 <飞控IP>                              # 【填 Q2】判据: 0% 丢包
# 环境自检口令后:
ros2 topic hz /fmu/out/vehicle_status_v1       # 判据: ~1.97Hz  ← 链路通的金标准
```
⚠️ 判链路**一律用 `topic hz`**,别用 `topic list`(发现竞态,假阴性)。
⚠️ 飞控上电后 ~10s 内 ping 不通正常(net.cfg 先 DHCP 再回落静态)。
⚠️ **若仿真机也在同一 WiFi**:SITL 默认落域 0,会与真机 XRCE 域 0 串台
   (真机 drone0 用 `/fmu`,SITL drone0 也用 `/fmu` → SITL 可能误发 ARM/setpoint 到真飞控)。
   飞场一般没仿真机;若在,SITL 一侧务必显式 `ROS_DOMAIN_ID=42` 隔离,或别在真机在线时跑 SITL。

## 2. 网络 / XRCE 改飞场网段【填 Q1/Q2】
> 台架用的是点对点 `192.168.77.x`;飞场按分配的网段(大概率 `10.41.10.x`)改。
> ⚠️ **别让 Jetson 两个网口同网段**:FC↔Jetson 点对点(`eno1`) 与 Jetson 取 VRPN 的网络(WiFi)
> 必须**不同段**,否则发往 VRPN 的包被塞进只通飞控的线里黑洞掉(症状极像"动捕没数据")。
> 保 `eno1` 的 `ipv4.never-default yes`,让 VRPN 包走 WiFi 默认路由。

**飞控侧**(QGC 或 `fc_configure.py`):
- SD 卡 `/fs/microsd/net.cfg`:`IPADDR=<飞控IP>` / `ROUTER=<网关>`【填 Q1/Q2】→ `netman update` → 重启飞控
- `fc_configure.py -g xrce --apply` 设 `UXRCE_DDS_CFG=Ethernet` → **重启飞控**(之后 `UXRCE_DDS_AG_IP` 才出现)
- `UXRCE_DDS_AG_IP` = **Orin NX IP**:
  🔴 **`fc_configure.py` 的 `xrce_ag_ip` 组把该值写死成 `192.168.77.100`(台架 Orin NX IP)**——
  飞场 Orin NX 换了 IP,**必须先改脚本里那个常量,或直接用 QGC 填**,否则飞控会把会话发去台架旧地址、连不上。
  (脚本自带 `as_int32`:IP 首字节≥128 要折成负数,QGC 手填则填自然整数。)
- `UXRCE_DDS_PRT=8888` / `UXRCE_DDS_DOM_ID=0`(出厂已是,核对即可)

**Jetson 侧**:
```bash
sudo nmcli con mod fc-link ipv4.addresses <OrinNX IP>/24    # 【填 Q2】
sudo nmcli con up fc-link
# ROS_DOMAIN_ID=0 已在环境口令里
```
判据:重复 §1 自检,`vehicle_status_v1` ~1.97Hz 恢复。

## 3. 动捕链路 bringup【填 Q5/Q6/Q7/Q8】
> 前提:动捕软件里已贴 marker、建刚体、跟踪稳定。

```bash
# 1) VRPN 客户端(可能在地面机器上跑;server 是动捕主机 IP,不是飞控 IP)
ros2 launch vrpn_mocap client.launch.yaml server:=<VRPN IP> port:=3883   # 【填 Q5】
ros2 topic list | grep vrpn         # 判据: 见 /vrpn_mocap/<刚体名>/pose 【填 Q6 刚体名】
ros2 topic hz /vrpn_mocap/<刚体名>/pose    # 判据: ≥50Hz 【核对 Q7】
```

**坐标系对齐(Q8)——最容易错,先想清楚再起桥**:
- 桥默认 **ENU→NED 转换**(`input_ned=false`)。VRPN 绝大多数是 ENU,通常保持默认。
- **若 Q8 答复动捕直接输出 NED**:§4 的 launch 直接传 `input_ned:=true` 走 NED 直通即可
  (launch 已透传到 `mocap_bridge_node.input_ned`)。单独起桥时同样 `-p input_ned:=true`。

```bash
# 2) 桥(ENU 情形:随 §4 launch 的 mocap:=true 自动起即可,无需单独跑这条)
ros2 run mpc_control mocap_bridge_node --ros-args -p drone_id:=0 -p rigid_body:=<刚体名>  # 【填 Q6】
```

**EKF2 收敛判据**(真动捕复验;台架只用假**静态**位姿验过,真机运动是首次):
```bash
ros2 topic echo --once /fmu/out/estimator_status_flags \
    --qos-reliability best_effort --qos-durability transient_local | grep cs_ev
    # 判据: cs_ev_pos / cs_ev_yaw / cs_ev_hgt = true, cs_ev_yaw_fault = false
ros2 topic echo --once /fmu/out/vehicle_local_position \
    --qos-reliability best_effort --qos-durability transient_local | grep -E 'xy_valid|z_valid|^x:|^y:|^z:'
    # 判据: xy_valid/z_valid=true, 位置与动捕真实位置一致(ENU→NED: N=y, E=x, D=-z)
```
- [ ] **坐标系实测**(比单看 flag 更硬):手持刚体沿 +东 移 1m,看 `vehicle_local_position` 的
      **y(E)** 增 ~1;沿 +北 移,看 **x(N)** 增。方向反/镜像 → Q8 约定或 `input_ned` 错。
- [ ] 🔴 **动捕覆盖包络实测**(`真机推进待办.md` B 段):**卷尺量不出**,标定体积 ≠ 场地尺寸。
      手持刚体走到计划活动半径的边缘(solo1 circle 位移到 ~3m、pair2/trio3 各机位),
      全程盯 `xy_valid` 不掉、pose 不跳。**掉了就把 `IN_*` 活动半径/围栏收到覆盖得住的范围**
      (改 `config/scenarios.yaml` 的 `IN_*` + `GF_MAX_HOR_DIST`/`GF_MAX_VER_DIST`)。
- [ ] **遮挡断流测试**(无桨、地面):手动遮 marker 数秒 → 桥应打
      `**一帧都没收到**` 或 `动捕位姿已 Xs 无更新` 告警;EKF 数秒内失效。确认告警会响、能听见。

⚠️ **共享原点门控(`calib_shared_origin=true`,launch 默认开)**:动捕全场共享一个原点,各机
`local` 是它在场地系里的**真实位置**(不是 ~0)。mpc_node 要求注入位置与场景出生点偏差
`< calib_shared_origin_tol=0.5m` 才锁定校准,否则 `calib STUCK` 守出生点、拒飞。
⇒ **飞机必须实际摆在 `scenarios.yaml` 的 births 标记点上**(solo1=场地原点),偏太多起不来
——这不是 bug,是拦"刚体名↔drone_id 接错致两机撞同一点"的安全门。

## 4. 无桨 + 动捕:3 场景就绪验证(**不解锁**)
> ⚠️ **只验就绪,不解锁跑任务**。无桨解锁跑任务 = 动捕报"没动"↔指令"要动"矛盾 →
> 控制器 windup、电机窜最大、不代表真飞、有过热风险。**任务轨迹逻辑已在 SITL 验过。**
> **桨确认拆掉。**

对 `IN_solo1_hover` / `IN_solo1_line` / `IN_solo1_circle` **各跑一遍**:
```bash
# 终端A(drone companion,Jetson):
ros2 launch mpc_control real_hardware_launch.py \
    drone_id:=0 scenario:=IN_solo1_hover \
    start_agent:=false auto_arm:=false mocap:=true rigid_body:=<刚体名>   # 【填 Q6】
# 终端B(地面站,可选但建议:让就绪门控真的走一遍):
ros2 launch mpc_control real_hardware_launch.py role:=leader scenario:=IN_solo1_hover
```
⚠️ `start_agent:=false` 因 Agent 已 systemd 自启(否则两个 Agent 抢 8888 端口)。
⚠️ `mocap:=true` 默认 ENU→NED;Q8 若答复 NED 直出,追加 `input_ned:=true`。

每个场景判据(不解锁下):
- [ ] `mpc_node` 日志:`calibrated [STABLE] ... world_birth≈动捕真实出生点`(**不是** STUCK)
- [ ] `mpc_node` 到 `waiting RC ARM+OFFBOARD`(arm=1 disarmed)
- [ ] FC `failsafe_flags`:`offboard_control_signal_lost=false` + `local_position/velocity/altitude_invalid=false`
- [ ] **参数包络核对**(防某场景把飞机放出安全范围/覆盖范围):`target_alt` / `safety_max_track_dist` /
      `safety_max_alt` / 围栏距离 —— 都在 §3 实测的标定体积内

> 台架无动捕时用 `tools/start_dryrun.sh`(假**静态**位姿,只验链路);飞场有真动捕,直接上面这条 launch。

## 5. 装桨 + 渐进放飞
> 飞场规程:异常**优先 Ctrl+C**(飞控自动降落),非紧急别直接拨 Kill。
> ⚠️ 台架只验过**静态**注入,运动注入未验——但那是台架伪影(真 IMU 静止 vs 假位姿运动矛盾)。
> 飞场真机真动、IMU 与动捕**同源**,该矛盾不存在;仍严格按 **hover → line → circle** 渐进兜住风险。

- [ ] **装桨**(确认桨向与电机转向匹配)、桨帽拧紧
- [ ] 场地中央、飞机摆到 births 标记点(§3 共享原点门控要求)、场内无人、飞手就位
- [ ] **启动顺序(严格)**:
      1) 动捕/VRPN 已在跑(§3) 2) `drone companion` launch → 等日志 `waiting RC ARM+OFFBOARD`
      3) 数据记录 `python3 diag_monitor.py --formation solo1 --log &`(留 CSV 复盘)
      4) **最后**起 `role:=leader`(它一发参考 + 就绪门控过就开动)
- [ ] **飞行控制/leader 终端保持聚焦,随时可 Ctrl+C**
- [ ] 飞手 **RC 解锁 → 切 OFFBOARD** → **solo1 hover 低空短时**
      🔴 真飞一律走**飞手 RC 解锁**;`auto_arm:=true` 只用于无桨台架,装桨后严禁(会自动解锁转桨)
- [ ] 落地 → `python3 analyze_flight.py <csv> --plot` 复盘(偏移/高度误差/最小间距/振动异响) → 无误再升级 **line → circle**
- [ ] ⚠️ **首飞前先在地面确认**:飞行中拨 C5 能否从 OFFBOARD 切回手动 Stabilized(本项目尚未实测)
- [ ] solo1 三态过关后再进 **pair2 → trio3**(多机:每架 `MAV_SYS_ID=id+1`、drone_id≥1 的 FC
      设话题命名空间 `-n px4_<id>`、各机 `UXRCE_DDS_DOM_ID=0`、地面站一个 `leader_node`)

## 6. 应急处置(优先级)
| 优先级 | 手段 | 结果 | 何时 |
|---|---|---|---|
| 1 | **Ctrl+C 停 `mpc_node`** | offboard 0.2s 丢 → `COM_OBL_RC_ACT=4` 自动降落 | 非紧急异常(首选) |
| 2 | **拨 C5 → Stabilized(低位)** | 飞手手动接管手飞 | 想亲自接管;定位丢时的保命模式 |
| 3 | **Kill(C8)** | 硬切电机、可能硬着陆 | 最后手段 |

⚠️ 动捕突然全断 → 桥告警 → EKF ~1s 失位置 → 飞控 `blind land`/`COM_OBL_RC_ACT=4`。
   这是设计内兜底,但**别指望它优雅**;真丢定位时优先级 2(手动接管)更稳。

### 自动失联降落(三层,无需人工干预)
| 失联类型 | 谁触发 | 机制 | 触发时长 |
|---|---|---|---|
| companion→飞控(mpc_node崩/Jetson死/XRCE断) | 飞控 | `COM_OF_LOSS_T`→`COM_OBL_RC_ACT=4(Land)` | 0.2s |
| 遥控失联(offboard中也生效) | 飞控 | `COM_RC_LOSS_T`→`NAV_RCL_ACT=3(Land)`;`COM_RCL_EXCEPT=0` 保证 offboard 不豁免 | 0.5s |
| **leader/协同失联**(WiFi丢但 companion 仍发 setpoint) | **companion(第2层)** | mpc_node 看门狗:OFFBOARD 中 leader 停 → settle→AUTO.LAND | **5s** |
- 第2层由 `real_hardware_launch.py comms_loss_land_s`(默认 5.0)控制,启动日志会打
  `第2层失联降落已武装`;设 `comms_loss_land_s:=0` 可关。leader 在 5s 内恢复则不触发。
- ⚠️ `COM_RCL_EXCEPT=0` 现已纳入 §0 参数体检(`fc_configure.py -g failsafe`),每次核验防被误改成 4。

## 附:常见坑速查(都实际踩过)
- **acados env**:非交互 shell 不读 `.bashrc`,`mpc_node` 崩 `libqpOASES_e.so` → 见顶部环境口令
- **`pkill -f` 自杀**:杀进程与后续任务拆成独立命令;pattern 别出现在同条命令里;用 `[x]` 方括号
- **`ros2 launch` 孤儿**:kill 掉 `ros2 launch` 父进程,`client_node` 子进程会活下来;
  清理要 `pgrep -f "vrpn_mocap.*client_node"` 连子进程一起杀
- **`ros2 topic list` 发现竞态** → 判链路用 `ros2 topic hz`
- **PX4 out 话题 QoS** = BEST_EFFORT + TRANSIENT_LOCAL,`ros2 topic echo` 要带 `--qos-*`
- **上电顺序不能反**:先 Jetson 后飞控
- **域号 = 0**(全链路);仿真机同网时 SITL 会串台,别在真机在线时跑 SITL(或 SITL 显式设 42)
- **QGC**:`Link0` 用 by-id 稳定名(重启后 ttyACM 改号也能连);USB 遥测流不稳,要稳走以太网
- **Jetson 非 git 仓库**:改了代码要手动 `git archive HEAD` 同步,`/commit-push`/`git push sim` 不到 Jetson
- **`fc_configure.py` 台架残留值**:`xrce_ag_ip` 组硬编码台架 Orin NX IP(192.168.77.100),
  飞场必须改;`GROUPS` 注释里"5×5 场地"是旧尺寸(实际 7×8.5m)
