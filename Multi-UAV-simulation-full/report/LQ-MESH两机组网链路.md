## 0. 现状与范围（先读这段）

- **为什么要 mesh**：替代飞场 WiFi 那条 ground↔air 链路（弱信号 + 多播发现不稳）。编队要各天空端
  **互发**预测轨迹/health（机间通信），不是"地面带几台从机"。
- **✅【台架 2026-08-10】**：AP/STA **星型**下 **STA↔STA 不互通**（电脑插地面端能 ping 全部；插一台
  天空端**进不去**另一台天空端）⇒ 星型会把机间通信**静默废掉** → **改用 MESH**（对等单跳，从机间直连）。
- **⚠️ 执行状态**：MESH 配置流程、FastDDS 单播 profile 均**已起草，尚未在 MESH 模式下端到端实测**。
- **与 FC 链路方案无耦合**：两机 mesh 验证**不需要接飞控**，纯电台 + 两台电脑即可跑完 L0–L3。
  FC 走串口(A方案)/以太网(B方案)是另一件事，见 §9。**动 FC 参数/接线等物理就绪 + 你明确再执行。**

## 2. 网络拓扑与 IP 规划

全网一张扁平 LAN：**`192.168.1.0/24`**，子网掩码 `255.255.255.0`（截图确认）。

| 设备 | IP | 备注 |
|---|---|---|
| 地面 PC / QGC / 配置电脑 | `192.168.1.100` | 配置期临时用 **【官方】`.123`** |
| Jetson drone1/2/3（挂 mesh 网卡） | `.201` / `.202` / `.203` | |
| LQ 模块管理 IP（地面/天空×3） | `.211` / `.221` / `.222` / `.223` | 见下方撞车提醒 |

- 🔴 **IP 撞车必须先解决**：出厂/台架时模块仍是 `.200`(地面)/`.202`/`.203`(天空)，与 **Jetson 规划的
  `.202`/`.203` 撞车**。切 MESH 时**一并把模块管理 IP 改到 `.211/.221/.222/.223`**，空出 `.201–.203` 给 Jetson。
- 飞控段 `192.168.77.x`、飞场段 `10.41.10.x` 与 `192.168.1.x` 都不冲突。
- ⚠️【推断】每台机的 mesh 网卡都要 `ipv4.never-default yes`（别抢默认路由，eno1 踩过）。

**两机最简分配（本轮验证用）**：
```
模块A(天空) 管理IP .221 ── 网线 ── 机A(Jetson/PC)  mesh IP .201
模块B(天空) 管理IP .222 ── 网线 ── 机B(Jetson/PC)  mesh IP .202
```

## 3. 模块配置（MESH 模式，逐台直连）

⚠️【推断】**逐台直连配置，别隔空翻**——把某台翻成 MESH 的瞬间它就从旧网掉线、够不到。

**【官方】每台步骤**（`配置/1.修改IP.md` + 网络设置界面）：
1. **硬件连接**：接天线 → 天空端接 12V 电源 → 天空端网口接电脑 →（地面端也上电）。
2. 电脑 IP 设为同网段 **`192.168.1.123`**；浏览器访问模块**当前 IP**（出厂 `192.168.1.200`）
   → 登录"**阿木实验室无线管理系统**"。
3. 左栏 **系统配置 → 网络设置**。界面分两栏：

   **本机设备参数（每台唯一）**
   | 字段 | 值 |
   |---|---|
   | 本机 IP 地址 | 按 §2 规划（`.221/.222/…`）**← 每台唯一** |
   | 子网掩码 | `255.255.255.0` |
   | 网关 IP 地址 | `192.168.1.1` |
   | 硬件/软件版本、设备ID、模块型号 | 只读（`LQ-M` / 软件 `1.1.9` 等） |

   **模块参数（★ 全网必须一致）**
   | 字段 | 值（截图实测） |
   |---|---|
   | **工作模式** | **MESH** |
   | 高带宽模式 | 默认**关**（除非需要更高带宽再开，会占更多频谱） |
   | ESSID | `test0001` |
   | 工作频率 Mhz | `2437--6ch`（⚠️ 与飞场 WiFi 信道错开，§8） |
   | 加密方式 | `SAE` |
   | 密码（>8 个字符） | `87654321`（正式部署建议改强密码，全网同步改） |
   | 电平阈值 | `-76`（邻居 RSSI 门限，弱于此判掉线；无线差可下调） |

4. 点击**保存** → 左栏 **维护 → 系统重启**。
5. 拔线换下一台，重复。
6. **【官网】** 全部翻 MESH + 配置一致后通电**自动组网**（对等，无需指定主从）。
   > ⚠️ 官方"单机配置"页原话是"通常只需要修改 IP 地址和工作模式"——但那是在 ESSID/频率/加密**已一致**
   > 的前提下；**两台若这几项不一致则组不上网**，务必逐台核对上表"全网一致"那组。
   > ✅ **【官网《Mesh组网快速上手》主/从设备截图实证】**：主设备(.200)与从设备(.201)的**工作模式都 = MESH**
   > （两张截图红框一致），**只有 `本机IP` 不同**（.200 / .201）。文档正文把它们叫"主设备(AP端)/从设备(STA端)"
   > **只是角色叫法，不是 AP/STA 星型模式**——实际全是对等 MESH。在线信息页也显示"无线组网模式:**mesh**、总数:2台、
   > 两台均在线、RSSI −18/−19"。⇒ **官方多机就是用这套对等 MESH，和我们台架切 MESH 的决定一致。**

## 4. 供电与天线（安全红线）

- 🔴【官方】**天线必须先装再通电**；用完/运输**拆 SMA 天线**。
- 🔴【官方】**地面端**：typec **5V/3A**。
  **✅【台架】供电坑**：电脑 USB/雷电口对**不发 PD 协商的哑负载**默认只给 **0.5–0.9A**，喂不饱 →
  症状像欠压/链路抖动。**用独立 5V/3A 充电头/充电宝 + 能过 3A 的线**。
- 🔴【官方】**天空端**：最大输入 **≤18V**，官方示例接 **12V**。接口 XT30（台架件）。
  - **【推断】X500 4S（14–16.8V）在 ≤18V 内 → 可 4S 直供**（PDB 引一路 XT30）。
    🔴 **绝不上 5S/6S**（满电 16.8V 离上限只剩余量、超了烧板）。
  - 母线脏、供电后抖动/丢包先怀疑电噪声 → 上 **BEC 4S→12V/2–3A** 隔离（更贴官方 12V）。
- ⚠️ 重量/CG：天空端 + 天线（+BEC）上机算进 X500 载重。

## 5. Jetson / PC 侧网络配置（mesh 网卡）

把接 mesh 模块的网卡配成 §2 的静态 IP，并禁止它抢默认路由。

**Jetson（nmcli；mesh 走新增的 USB 网卡如 `eth1`，见 §9 结论；`<IFACE>` 换成实际网卡名）**：
```bash
sudo nmcli con add type ethernet ifname <IFACE> con-name mesh-link \
     ipv4.method manual ipv4.addresses 192.168.1.101/24 \
     ipv4.never-default yes ipv6.method ignore autoconnect yes
sudo nmcli con up mesh-link
```
> 🔴 **2026-08-19 现场改编址：机载电脑一律 `.10x`（A10=`.101` / A08=`.102`），
> 严禁再用 `.20x`。** 三台 LQ 电台自身占用 `192.168.1.200` / `.202` / `.203`
> （识别特征：80+23 端口全开，web 标题「阿木实验室无线网络系统」，`Server: Boa/0.94.13`）。
> A08 原配 `.202` 与电台直接冲突，现场表现是**同一 IP 在不同机器上解析到不同 MAC**
> ——从 A10 看是 Jetson、从地面 PC 看是电台并被 RST。飞行中 ARP 一翻，机间 DDS 即断。

**PC（Windows 临时代一端）**：设置→以太网→IP 手动 `192.168.1.123/24`，网关留空
（🪟 改 IP 需**管理员**，非管理员 `New-NetIPAddress` 报 `Access denied`）。

- ⚠️ **关掉 Jetson 自带 WiFi 或让 WiFi 错频**：否则 2.4G 撞频 + DDS 可能悄悄走 WiFi（假通过，§7/§8）。
- ✅ 验证：`ip addr show <IFACE>` 有 `192.168.1.20x`、`ip route` 里这条**不是** default。

## 6. FastDDS 单播发现 profile

FastRTPS 默认**多播**发现，无线多播极不稳 → 改**单播**。配套件 **`deploy/mesh_fastdds_profile.xml`**（已随仓库）。

- **机制**：`SIMPLE` + `initialPeersList` 单播；手动指定 `metatrafficUnicastLocatorList`=本机 mesh IP
  → Fast-DDS 弃用默认多播 locator（禁多播 + 钉在 mesh 网卡）。`leaseDuration` 放宽到 12s，避免误判掉线。
- **每台只改一行**：`<metatrafficUnicastLocatorList>` 的 `<address>`=**本机 mesh IP**；`<initialPeersList>`
  全网一致，含 `127.0.0.1`（给本机 XRCE Agent）。
- **三个环境变量**（systemd 里 `Environment=` 显式写，非交互 shell 不读 `.bashrc`）：
  ```bash
  export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
  export ROS_DOMAIN_ID=0
  export FASTRTPS_DEFAULT_PROFILES_FILE=/绝对路径/deploy/mesh_fastdds_profile.xml
  ```
- **两机验证**：只需两台的 mesh IP（+ 各自 `127.0.0.1`）；profile 里多余的离线条目无害（Fast-DDS 周期探测、失败静默），保留即可。
- ⚠️ XRCE Agent 的 systemd **不用**加此 profile（它只服务本机 FC↔mpc_node，靠 `127.0.0.1` 被本机 mpc_node 单播发现）。

## 7. 分层验证流程（L0 → L3）

**一层是下一层的前提。** 关键铁证：**机插一台天空端 ping 另一台天空端**——星型不通、MESH 应通。

| 层 | 目标 | 命令/判据 | 通过标志 |
|---|---|---|---|
| **L0 电台** | 两模块自动组 mesh | **【官方】系统配置 → 在线信息**（表头：序号/IP/设备ID/**设备接收 RSSI(dBm)**/设备状态）；看信号指示灯 | 表里看到**对方节点=在线** + RSSI；**信号灯常亮** |
| **L1 IP** | mesh 转发从机间流量 | 机A `ping 192.168.1.102` | **通**（星型此处不通 = MESH 生效铁证） |
| **L2 DDS** | 跨机 DDS 单播发现 | 两台各起 talker/listener（下）；**务必关 WiFi/never-default 下验** | listener 收到 talker 消息 |
| **L3 ROS2** | 项目话题跨机可见 | `ros2 topic hz`；或 mpc_node 邻居预测/health | 目标话题稳定出数 |

- **✅【官方】L0 在线信息页**就是核节点+RSSI 的地方（截图实证：ap/sta 时只 1 台在线、RSSI 栏在）。
- **【台架】指示灯**：运行灯闪=已进工作模式（正常）；信号灯**常亮=连接成功 / 闪=无连接**（看到"闪"多半不是供电故障）。
- **L2 跨机 DDS 测试**（两台各一条，先都 source + 导出 §6 三 env）：
  ```bash
  # 机A：
  ros2 run demo_nodes_cpp talker
  # 机B：
  ros2 run demo_nodes_cpp listener      # 收到 "I heard:[Hello World: N]" = 跨机发现成功
  ```
  🔴 **务必关 WiFi/never-default 生效下验**：否则 DDS 可能悄悄走 WiFi**假通过**，一到飞场就废。
  先 `nmcli radio wifi off`（或拔 WiFi），只留 mesh 网卡。发现不全 → profile 加 `maxInitialPeersRange` 或核 `initialPeersList`。

## 8. 关键风险与坑（速查）

1. 🔴 **FastDDS 默认多播**（最可能翻车）→ 上单播 profile（§6）；验证**关 WiFi** 排除假通过。
2. 🔴 **2.4G 撞频**：LQ 频率（`2437`/6ch）与飞场 WiFi 信道错开；建议关 Jetson 自带 WiFi。
3. **星型 STA↔STA 不通**（✅台架）→ 用 MESH，别用 AP/STA。
4. **供电喂不饱**（✅台架）：电脑 USB 口对哑负载只给 0.5–0.9A → 独立 5V/3A 充电头。
5. **管理 IP 撞车**：模块 `.200/.202/.203` 与 Jetson 规划撞 → 挪到 `.211/.221/.222/.223`。
6. **隔空配置掉线**：逐台直连配（§3）。
7. **never-default 必配**：mesh 网卡别抢默认路由（eno1 踩过，会打断 WiFi SSH）。
8. **动捕 VRPN 归属**：动捕 PC 若只在飞场 WiFi 段、Jetson 又不连 WiFi → 收不到 VRPN；需让动捕 PC 进 `192.168.1.x`，或保留一条到飞场网的路。

## 9. QGC / MAVLink 走哪（官方"多机控制"结构已核到）

> **来源补充**：阿木官网《Mesh组网快速上手》原文可取（`curl` **正斜杠+URL编码**能过、反斜杠会 500）：
> `https://docs.amovlab.com/amov-lq-wiki/src/各型号快速上手/Mesh组网快速上手.md`。配套网络设置界面截图
> （主/从设备）也已下载核对。**这就是阿木官方"用来做多机控制"的结构。**

**✅【官方截图实证】官方"多机控制"结构 = 每机 FC 串口 →LQ 串口透传→UDP 端口，经 mesh 汇到地面端**：
- LQ 模块的"**串口配置参数**"里，**每个模块有 3 路串口，各串口→UDP 转发**：连接类型 UDP、开启服务器、
  主设备默认**监听端口 8080 / 8081 / 8082**（截图确认）。
- 各天空端 FC 的 MAVLink 走一路 **LQ 串口** → 透传过 mesh → 地面端把每机暴露成一个 **UDP 端口**。
- 地面端电脑网线接 LQ 地面端网口；**QGC 每机加一条 UDP 连接**（Type=UDP，Port `8081/8082/…/8085`，
  `使用/连接.md` 演示 5 机）。
- ⚠️ 注意：官方这套多机是**地面端(基站) ↔ 各机**的 MAVLink 汇聚（给 QGC 看/控），**不是**各机之间互发。
  本项目要的**机间通信(STA↔STA 发预测/health)走的是 LAN 口上的 ROS2/DDS**（§6/§7），两条流并存、各走各的。

> ⚠️ **串口不够用——这块飞控只有一个 TELEM 口**（下）。

### 🔴 结论：需加一块 USB-网口（USB 转以太网），因零一飞控只有一个 TELEM 口

**✅【实测】零一 X6 Air+ 只有一个 TELEM 口（TELEM1），没有 TELEM2/3。**
证据：出厂全量参数快照 `report/fc_params/X6Air+_v1.16.0_出厂快照_20260722.csv` 里串口波特率参数
**只有** `SER_TEL1_BAUD` 和 `SER_GPS1_BAUD` 两条——PX4 只对板子实际引出的口生成串口参数，
缺 `SER_TEL2_BAUD` 即物理上没有 TELEM2。对外通信口 = **TELEM1(串口) + GPS1(串口) + 网口**。
> ⚠️ 判断参数是否存在**只能以全量 dump 为准**：`param_request_read` 对不存在的参数会返回**虚假响应**
> （`SER_TEL2_BAUD`/`SER_EXT2_BAUD` 都中招过）。

**为什么这导致要加 USB-网口**：一个 TELEM 串口被 XRCE / 3DR 数传 / QGC(官方 LQ 串口透传法) 争用，挤不下。
**结论 = 保持 FC↔Jetson 走原生网口（eno1，不动已验过的 offboard 通路），给 Jetson 加一块 USB 转以太网网卡
专供 mesh 的 LAN 侧（ROS2/DDS/SSH/VRPN）** —— 即下表 **B 方案**。**（用户 2026-08-12：先不改 FC，先记进报告。）**

**✅ B 方案顺带把 QGC 也解开了**（重要）：B 方案下 **XRCE 走以太网 eno1 → TELEM1 空出来**，正好接官方那套
**LQ 串口透传**（TELEM1 → LQ 串口1 → UDP 8081 → QGC），不用再靠 `tools/mav_relay.py` 中转。于是三条流各走各的、互不争用：

| 流 | FC 侧 | 走哪 |
|---|---|---|
| offboard 控制(XRCE/ROS2 setpoint) | **网口** | eno1 点对点 → Jetson（已验，不动） |
| 机间通信(预测/health, DDS) | — | Jetson **USB 网卡 → LQ LAN 口 → mesh** |
| QGC MAVLink | **TELEM1 串口** | → LQ 串口 → UDP 8081 → 地面端 → QGC（官方法） |

（3DR 数传若还想保留，则和 QGC 争 TELEM1，二选一；有了 LQ 串口透传，3DR 可省。）

**A/B 方案对照（FC↔Jetson 链路，正交于 mesh）**：

| | A 方案（串口，存档） | **B 方案（因单 TELEM 口→采纳方向）** |
|---|---|---|
| FC↔Jetson | TELEM1 串口(ttyTHS1,921600) | **原生以太网 eno1**(192.168.77.x，已验 `vehicle_status_v1` 1.98Hz 从未断) |
| mesh 走哪 | eno1 | **USB3 千兆网卡**（新增，如 eth1，mesh IP 192.168.1.20x） |
| 串口占用 | TELEM1 被 XRCE 占 → QGC/数传只剩 GPS1 一路 | **TELEM1 空出 → 接 LQ 串口透传给 QGC（官方法）** |
| 代价 | 串口抗噪/带宽/延迟不如以太网、改控制通路要台架重验 | **多一块 USB 网卡（~几十元）**，offboard 通路不动 |

> ⚠️ Jetson 的 USB 网卡接口也要 `ipv4.never-default yes`（别抢默认路由，eno1 踩过）；USB 网卡偶发抖动
> 也不碰 offboard（故障域与控制命脉分开）。
> **两机 mesh 验证（§3–§7）不需要 QGC，可先不管。** QGC 用官方 LQ 串口透传法(§9 上文)即可，`tools/mav_relay.py`
> 中转桥在 B 方案下不再必需（留作以太网直连 QGC 的备选）。
