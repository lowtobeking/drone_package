本文件是 **SITL 仿真**启动命令。里面所有 `leader_radius:=10.0` / `S*` 场景 / `max_distance:=20`
都是**室外/仿真尺度（直径 20m）**，飞场只有 7×8.5m —— **严禁在飞场真机上照用，会直接撞墙/撞网。**

飞场真机**只用** `real_hardware_launch.py` + **`IN_*` 场景**（已按 7×8.5m 场地缩放，见
`config/scenarios.yaml`；离场地中心位移 ≤3.0m）。例：
    ros2 launch mpc_control real_hardware_launch.py role:=leader scenario:=IN_pair2_line
可用室内场景：`IN_solo1_{hover,line,circle}` / `IN_pair2_{hover,line,circle}` / `IN_trio3_{hover,line}`。
⚠️ 圆周"离起飞点最远 = 2×radius"；⚠️ 放大轨迹已同步放开 FC 围栏 `GF_MAX_HOR_DIST=3.0`
（`fc_configure.py -g geofence --apply`）；⚠️ **到场先量动捕标定体积**，小于 3.0m 半径要再缩。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 拔掉 Orin NX / 机载电脑的 USB 线
   （其网口上的 ROS2/DDS 会把 Agent 拖到 timesync RTT 1000ms+，全员 ping 超时断连；拔线即恢复）

2. ⚠️ 不要设置 ROS_LOCALHOST_ONLY=1
   2026-07-28 实测坐实：这会导致 MicroXRCEAgent 的内部 DDS participant 完全无法被 ROS2 发现
   （ros2 topic list 永远零 fmu 话题，drone 卡死 arm=0 解不了锁）。根因是 Agent 走 XRCE 协议
   创建 participant，不经过 FASTRTPS_DEFAULT_PROFILES_FILE 的默认 profile 查找。
   - config/agent_localhost.xml 白名单对当前 MicroXRCEAgent 版本无效，终端2 不需要再带
     FASTRTPS_DEFAULT_PROFILES_FILE，直接 `MicroXRCEAgent udp4 -p 8888` 即可
   - 外部 WiFi 设备组播干扰目前观测影响有限；若以后又出现全员断连，优先怀疑"新连了什么设备"，
     不要重新打开 ROS_LOCALHOST_ONLY

3. 启动顺序铁律：Agent（终端2）必须先于 PX4（终端3）
   PX4 首次握手失败后不再重试（日志显示 uxr_create_session failed 即此）

任务完成自动降落（第1层）  ← 收场别再用 Ctrl+C（会连仿真栈一起端掉→飞机直接掉=炸机）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

原理：leader 单点广播 LAND → 各机零速悬停 land_settle_s(默认1.5s) 刹掉编队速度
→ 各自切 AUTO.LAND 垂直下降 → 触地自动上锁。降落段去掉机间协同，靠飞行段已拉开的
水平间距 d_safe，垂直下降不收敛 = 构造上无碰撞。适用于 solo1~grid9 任意规模。

方式A｜运行中手动一键（推荐；任何"已在跑"的场景都能用，不用重启）：
  另开一个终端（须与终端4 同一 ROS 环境 / 同一 ROS_DOMAIN_ID）：
  cd ~/ros2_control_mpc_ws && source install/setup.bash
  ros2 param set /leader_node trigger_land true

方式B｜启动即定时（把降落写进 launch 命令，运动开始 N 秒后自动降）：
  在终端4 的 launch 命令末尾追加 mission_duration:=N（秒）。例（5机十字圆周飞60秒后自动降）：
  ros2 launch mpc_control swarm_launch.py formation:=cross5 leader_mode:=circle leader_speed:=1.5 leader_radius:=10.0 mission_duration:=60
  说明：mission_duration 从"运动开始"起算；缺省 0 = 禁用，保持旧行为、不自动降（不影响批量回归）。

降落成功判据：
  终端2 的 PX4 日志出现 "Landing detected" + "Disarmed by landing"（逐台）；
  diag_monitor 各机 ARM 由 ARMED → DISARMED。

⚠️ 真机在线时先做 domain 隔离再降落：SITL 的 drone0 用非命名空间 /fmu，与真机 X6 Air+
   （domain 0）同一套话题，降落/解锁指令会打到真飞控。SITL 一侧务必显式 ROS_DOMAIN_ID=42，
   或先停 Jetson 的 microxrce-agent（ssh jetson "sudo systemctl stop microxrce-agent"，可逆）。

通信失联自动降落（第2层，兜底；2026-07-31 新增）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

跟第1层不同：这层不靠 leader 广播，是**各机 mpc_node 自带的看门狗**——OFFBOARD 飞行中若超过
comms_loss_land_s 秒没收到 /leader/state（例如 leader_node 崩了、WiFi 断），本机自动触发降落，
不依赖 leader 存活。可选"先冻结"中间态：失联超过 comms_loss_hold_s（须 < comms_loss_land_s）
但还没到降落阈值时，先原地悬停、不追陈旧参考，避免冲向失效前的旧目标点；到降落阈值仍未
恢复才真正 AUTO.LAND。默认全部关闭（comms_loss_land_s=0.0），须显式加参数才生效。

启用（在终端4 的 launch 命令末尾追加）：
  ros2 launch mpc_control swarm_launch.py formation:=<队形> ... comms_loss_land_s:=5.0 comms_loss_hold_s:=1.0
  （comms_loss_hold_s 可省略，省略则没有"先冻结"，直接等满 comms_loss_land_s 秒后降落）

启动日志确认已武装：
  第2层失联降落已武装：OFFBOARD 中 leader 停 5.0s → 自动降落（；leader 停 1.0s 先就地冻结）

测试触发（SITL 模拟 leader 崩溃/失联；真机场景不要手动杀 leader_node 测试，先在 SITL 跑通）：
  kill $(pgrep -f '__node:=leader_node')
  （用 PID kill 最稳；pkill -f leader_node 容易自己把带 leader_node 字样的命令行也杀掉）

触发后应依次出现（先冻结阶段仅在配了 comms_loss_hold_s 时才有）：
  [d0] leader 失联 N.Ns(>1.0s) — 就地悬停，不追陈旧参考（5.0s 仍未恢复则降落）
  [d0] 通信失联：已 5.x s 未收到 leader (阈值 5.0s) — 触发自动降落
  [d0] LAND settle: 零速悬停 1.5s 后切 AUTO.LAND
  [d0] LAND: settle 完成 → 命令 AUTO.LAND，停 offboard 流交给 PX4
  （终端2 PX4 日志）Landing detected + Disarmed by landing

已验证：单机触发/不误触发、pair2 双机同时触发+间距3.02m无碰撞、先冻结阶段 solve=0(真停了)。
每架次(重新解锁)后看门狗自动重新武装，不用手动 reset。

⚠️ 真机在线时同样要先做 domain 隔离（见上方"第1层"末尾那条），否则 SITL 侧的失联测试会把
   降落指令打到真飞控。
